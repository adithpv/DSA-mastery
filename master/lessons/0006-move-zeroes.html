Pattern · Stable compaction + fill

Move Zeroes

First compact every non-zero value into the front. Then the unfinished suffix has only one possible meaning: zeroes.

💡
Recognition signal
When selected values move to one side while the other values keep their order, think: stable compaction, then fill the gap.

Two phases

010312

Phase 1: write non-zero values forward.
Phase 2: fill everything after them with zero.

State jobs

  • i reads all original values.
  • p1 is the next position for a non-zero value.
  • After compaction, p1 is the start of the zero suffix.

Walk it: [0, 1, 0, 3, 12]

Skip the first zero

010312

p1 remains 0 because no non-zero value has been written.

Compact 1 into the front

110312

Write at index 0, then move p1 to 1.

Compact all non-zero values

1312312

The valid prefix is final. Old suffix values are stale and no longer meaningful.

Fill the remaining suffix

131200

Fill from p1 = 3 to the end with zeroes.

The invariant

During compaction, nums[0...p1-1] contains exactly the non-zero values seen so far, in their original order.

After compaction, that prefix is final and every remaining position belongs to the zero suffix.

The algorithm

let p1 = 0;

for (let i = 0; i < nums.length; i++) {
    if (nums[i] !== 0) {
        nums[p1] = nums[i];
        p1++;
    }
}

for (let j = p1; j < nums.length; j++) {
    nums[j] = 0;
}

What to remember

Two loops are still O(n). At most n + n operations means 2n; Big O drops the constant.

O(n) timeOne compact pass and one fill pass.
O(1) spaceNo growing result array.

Primary source: LeetCode 283. Pattern reference: Read/write pointers.

Check your memory

What does p1 mean after phase 1?

It is both the number of non-zero values and the first position that must become zero.

Why is order preserved?

The reader encounters non-zero values left to right, and the writer stores them in exactly that same sequence.
