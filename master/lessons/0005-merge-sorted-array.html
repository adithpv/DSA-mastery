Pattern · Backward merge

Merge Sorted Array

The free space is at the end, so fill it with the largest remaining values. Working backward protects unread data.

💡
Recognition signal
When two arrays are sorted and the first has empty slots at its end, think: compare from the right and write from the right.

The three pointers

256
p1 = 3p2 = 6write = last slot

Pointer jobs

  • p1 points to the largest unused real value in nums1.
  • p2 points to the largest unused value in nums2.
  • i points to the empty destination for the larger one.

Walk it: [1,2,3,_,_,_] + [2,5,6]

Compare 3 and 6

123__6

6 is larger, so it owns the last position. Move p2 and i left.

Compare 3 and 5

123_56

5 is the next-largest remaining value.

Compare 3 and 2

123356

Now 3 wins. Move p1 left.

Place the remaining 2 from nums2

122356

When nums2 is exhausted, leftover nums1 values are already in place.

The invariant

Before every write, all positions to the right of i contain the correct largest values in final sorted order.

The largest remaining candidate always belongs at the current rightmost empty position.

The algorithm

let p1 = m - 1;
let p2 = n - 1;

for (let i = m + n - 1; i >= 0; i--) {
    if (p2 < 0) break;
    if (p1 >= 0 && nums1[p1] > nums2[p2]) {
        nums1[i] = nums1[p1--];
    } else {
        nums1[i] = nums2[p2--];
    }
}

What to remember

Direction is the trick. Starting at the front can overwrite a real nums1 value before it is compared. Empty space at the end is your safety zone.

O(m + n) timeEvery value moves at most once.
O(1) spaceThe result uses nums1's capacity.

Primary source: LeetCode 88. Pattern reference: Backward merge.

Check your memory

Why can we stop when nums2 is empty?

Any unused nums1 values already occupy the correct front positions.

What is final after every iteration?

The suffix to the right of the write pointer is final and sorted.
