Pattern · Running prefix state

Best Time to Buy Stock

Treat today as the selling day. You only need one fact about the past: the cheapest eligible buy price.

💡
Recognition signal
When the current choice depends on the best earlier value and order matters, carry a small summary of the prefix.

The picture

715364
buy so far = 1sell today = 6profit = 5

Every price gets one chance to be “today's selling price.”

State jobs

  • min remembers the cheapest price seen so far.
  • maxProfit remembers the best valid profit so far.
  • Today's candidate is price - min.

Walk it: [7, 1, 5, 3, 6, 4]

Day 1: establish the past

715364

min = 7, maxProfit = 0. No earlier day exists yet.

Day 2: find a cheaper buy

715364

Selling at 1 is not profitable. Update min from 7 to 1.

Day 3: first useful profit

715364

Selling at 5 after buying at 1 gives 4. Save it as the best.

Day 5: improve the answer

715364

6 - 1 = 5. This becomes the final maximum profit.

The invariant

After each day, min is the cheapest price in the scanned prefix, and maxProfit is the best valid buy-before-sell profit inside that prefix.

Checking every selling day against its cheapest earlier buy covers every best ending.

The algorithm

let min = prices[0];
let maxProfit = 0;

for (const price of prices) {
    maxProfit = Math.max(
        maxProfit,
        price - min
    );
    min = Math.min(min, price);
}
return maxProfit;

What to remember

Global min + global max is unsafe. The maximum price might occur before the minimum, which would mean selling before buying.

O(n) timeEach day is visited once.
O(1) spaceOnly two running facts are stored.

Primary source: LeetCode 121. Pattern reference: Running prefix state.

Check your memory

What question do we ask on every day?

“If I sell today, what profit do I make using the cheapest eligible earlier price?”

Why does a decreasing array return zero?

No selling price exceeds an earlier buying price, so the best profit never rises above its initial zero.
