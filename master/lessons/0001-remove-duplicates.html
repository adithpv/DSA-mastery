Pattern · Read/write pointers on sorted input

Remove Duplicates

One pointer discovers values. One pointer protects the unique prefix. Sorted order makes the decision local.

💡
Recognition signal
When you see “sorted,” “in-place,” and “return the number of unique values,” think: keep a compact unique prefix.

Pointer jobs

  • i reads every candidate from left to right.
  • x points to the last unique value already kept.
  • nums[0...x] is the finished unique prefix.

The invariant

Before every comparison, nums[0...x] contains every unique value seen so far, exactly once and in sorted order.

This is the reason the algorithm works—not just a description of the code.

The algorithm

if (nums.length === 0) return 0;
let x = 0;

for (let i = 1; i < nums.length; i++) {
    if (nums[i] !== nums[x]) {
        x++;
        nums[x] = nums[i];
    }
}
return x + 1;

What to remember

Index vs count: x is the last valid index, so the count is x + 1. This is the easiest mistake in this problem.

O(n) timeEach value is scanned once.
O(1) spaceThe same array stores the result.

Primary source: LeetCode 26. Pattern reference: Read/write pointers.

Check your memory

Why is sorted order important?

Duplicates are adjacent, so comparing with the last unique value is enough to detect a new one.

Why return x + 1?

x is an index starting at zero. A last index of 2 means there are three values.
